# 企業員工大會抽獎系統 · 企劃書

> 版本 1.0 ｜ 對象：100～300 人實體活動 ｜ 設備：管理電腦 ＋ 大型投影螢幕 ｜ 規則：每位員工最多中獎一次

---

## 1. 專案目標

| 目標 | 衡量方式 |
|---|---|
| 現場零中斷 | 全程離線，不依賴網路與後端 |
| 結果零爭議 | 每人限中一次、亂數可追溯、紀錄可匯出 |
| 氣氛到位 | 每輪 8～10 秒的完整緊張曲線（蓄勢→翻牌→假動作→揭曉） |
| 主持人可掌控 | 節奏、獎項、加碼、撤銷皆由操作者決定，系統不自動推進 |
| 失誤可回復 | 任何一輪都能整輪撤銷，人員自動回到候選池 |

## 2. 場景與限制

- **人數**：100～300 人（名單一次載入，畫面只顯示姓名＋部門）
- **設備**：操作筆電（控制台）＋ 投影機（舞台畫面），採 Windows 延伸桌面
- **規則**：每人最多中獎一次；獎項分輪（參加獎 → 三獎 → 二獎 → 頭獎），可臨時加碼
- **環境風險**：場地網路不可靠、現場燈光暗、觀眾距離遠（字要夠大）

## 3. 設計原則

1. **單機優先**：純靜態網頁，雙擊即用。沒有伺服器就沒有連線失敗。
2. **控制台是唯一真相**：中獎者在控制台以 `crypto` 亂數抽出並立即落盤，投影畫面只負責「演出」。
3. **動畫與結果解耦**：即使投影畫面當掉，抽獎結果依然正確且已記錄。
4. **節奏由人控制**：抽完一輪就停住，主持人說話、拍照、頒獎後再按下一輪。
5. **優雅降級**：沒有音效照樣有動畫；沒有投影照樣能抽；專案檔可整包複製到任何電腦。

## 4. 系統架構

```
┌─────────────────────────────┐        postMessage / BroadcastChannel        ┌─────────────────────────────┐
│  index.html  控制台（筆電）  │ ───────────────────────────────────────────▶ │  stage.html  舞台（投影機）  │
│                             │                                              │                             │
│  LuckyStore（資料層）        │ ◀─────────────────────────────────────────── │  動畫導演（時序）            │
│   ├ 名單 / 獎項 / 中獎紀錄   │        hello · pong · draw-done · unlocked    │   ├ Canvas 粒子 FX           │
│   ├ crypto 亂數抽獎          │                                              │   ├ WebAudio 合成音效        │
│   └ localStorage 落盤        │                                              │   └ CSS 階段動畫             │
└─────────────────────────────┘                                              └─────────────────────────────┘
             │
             └─ 匯出 CSV / JSON 備份（活動後存檔、換電腦還原）
```

### 4.1 模組職責

| 檔案 | 職責 |
|---|---|
| `js/bus.js` | 雙軌訊息匯流：`window.postMessage`（直送對方視窗）＋ `BroadcastChannel`（同源廣播），以訊息 id 去重 |
| `js/store.js` | 狀態機與資料層：名單解析（CSV/TSV/貼上）、獎項、抽獎演算法、撤銷、統計、CSV 匯出、localStorage |
| `js/console.js` | 控制台 UI：獎項籌碼、抽獎按鈕、名單/獎項/紀錄/設定四個分頁、彈窗、快捷鍵、連線狀態 |
| `js/stage.js` | 舞台動畫導演：階段機（idle/charge/roll/lock/reveal/result/blackout）、翻牌時序、假動作、多人揭曉 |
| `js/fx.js` | Canvas 特效：漂浮餘燼、向心漩渦、彩帶爆發、衝擊光環 |
| `js/audio.js` | WebAudio 即時合成：滴答、呼嘯、心跳、鼓聲滾奏、上升音、號角、低頻嗡鳴（完全沒有音檔） |

### 4.2 訊息協定

| 方向 | 訊息 | 內容 | 說明 |
|---|---|---|---|
| 舞台→控制台 | `hello` | `{ unlocked }` | 載入時與每 4 秒廣播，供控制台重新取得視窗參考 |
| 控制台→舞台 | `state` | 名單統計、獎項、設定、候選姓名 | 任何資料變更即推送 |
| 控制台→舞台 | `draw` | `{ roundId, prize, winners[], count, poolNames, settings }` | **結果已定案**，舞台只演出 |
| 舞台→控制台 | `draw-done` | `{ roundId }` | 解鎖控制台按鈕 |
| 控制台→舞台 | `idle` / `blackout` / `test` / `setting` | — | 待機、黑屏、測試、音效開關 |
| 雙向 | `ping` / `pong` | — | 每 3 秒心跳，9 秒無回應視為斷線 |

> 抽取邏輯只存在控制台：舞台收到的 `winners` 是既成事實，動畫不會改變結果。

### 4.3 資料模型

```js
{
  eventName: "聖誕晚會抽獎",
  roster:    [{ key, name, dept, empNo }],        // key = 員工編號 或 姓名|部門
  prizes:    [{ id, name, count, tier }],          // tier 1=金(頭獎) 2=紅 3=紫 4=青
  winners:   [{ roundId, prizeId, prizeName, key, name, dept, empNo, ts, poolSize }],
  excluded:  [key],                                // 不參與者
  settings:  { spinMs, tease, sound, showEmpNo, allowRepeat }
}
```

## 5. 抽獎公平性設計

1. **亂數來源**：`crypto.getRandomValues()`（瀏覽器 CSPRNG），非 `Math.random()`。
2. **演算法**：Fisher–Yates 洗牌後取前 N 名，確保每個人機率相同。
3. **不重複**：候選池 = 全名單 − 已中獎 − 已排除；預設 `allowRepeat=false`。
4. **名額超出保護**：需求人數大於候選人數時自動截斷並提示，不會抽到重複或不存在的人。
5. **可追溯**：每筆紀錄保存 `roundId`、時間戳、當時候選池人數，匯出 CSV 即為公告依據。
6. **可回復**：撤銷以「輪」為單位，該輪所有人一起回到候選池，避免人為挑選爭議。
7. **現場可驗證**：控制台的「中獎紀錄」與投影畫面同步，觀眾可即時比對。

## 6. 操作流程（SOP）

### T-7 天｜準備
- 取得人資名單（姓名／部門／員工編號），確認同名同姓處理方式。
- 試算獎項與名額：總中獎人數 ≤ 參與人數；預留 10% 加碼空間。
- 準備音源輸出（HDMI 音訊或外接喇叭）。

### T-1 天｜彩排
1. 用**同一台筆電、同一個瀏覽器**開啟 `index.html`。
2. 匯入正式名單 → 檢查人數、部門是否有亂碼。
3. 設定大螢幕：延伸桌面 → 開啟投影畫面 → 拖到投影機 → 點擊啟動 → `F` 全螢幕。
4. 用 3～5 人試抽，確認：字級、音量、動畫節奏、假動作長度。
5. 匯出備份 JSON，存到桌面與隨身碟各一份。

### 活動當天｜上場
1. 開機 → 開啟控制台 → 投影畫面 → 點擊啟動（音效）。
2. 按「測試投影」確認訊號。
3. 依獎項由小到大抽；每輪抽完停住，主持人口播、頒獎。
4. 長官加碼 → 「臨時加碼」建立獎項 → 直接抽。
5. 抽錯人 → `Ctrl + Z` 撤銷整輪 → 重抽。
6. 中場休息 → `B` 黑屏。

### 活動後｜收尾
1. 「匯出 CSV」給人資公告。
2. 「匯出備份」存檔（含名單與設定，可完整重現）。
3. 若需留存公正性紀錄，保留 CSV 的時間戳與候選池人數欄位。

## 7. 動畫分鏡（以頭獎、預設 4.2 秒為例）

| # | 階段 | 時間 | 畫面 | 音效 | 技術 |
|---|---|---|---|---|---|
| 0 | 待機 | — | 微光「敬請期待」、餘燼緩慢上飄、光束緩轉 | 無 | CSS + Canvas 餘燼 |
| 1 | 蓄勢 | 0–1.9s | 光束收束、能量核心亮起、漩渦粒子向中心匯聚、**背景浮現候選人姓名雲**、「？？？」脈動 | 呼嘯 → 心跳 ×2 → 低頻嗡鳴 → 上升音 | `charge`、`FX.vortex`、`FX.nameCloud`、`core` |
| 2 | 翻滾 | 1.9–6.4s | 姓名每 30～50ms 高速翻牌、模糊與微震、金色光暈、背景姓名持續流動 | 鼓聲滾奏（越抽越快）＋滴答 | `roll`、`spinReel`、`drumroll` |
| 3 | 假動作 | ~5.0–5.5s | 速度驟降幾乎停止，定在一個「假名字」上並定住 | 心跳加重、低頻下沉 | 時間曲線 0.755–0.865 段 |
| 4 | 回馬槍 | 5.5–6.0s | 突然再加速、模糊拉滿 | 上升音 0.6s | 同上，`riser(0.6)` |
| 5 | 定格 | 6.4–7.0s | 真名出現、畫面輕微震動、能量核心收縮 | 心跳 ×1.35 ＋低頻衝擊 | `lock`、`lockShake` |
| 6 | 揭曉 | 7.0s | **72 道光爆射線**自中心炸開、名字彈出放大、**全場鏡頭推進＋畫面震動**、**左右彩帶加農炮**、背景姓名向外炸散、部門滑入 | 號角（依等級 3～6 音）＋衝擊＋閃亮 | `reveal`、`rays`、`slotPunch`、`shake`、`FX.burst`、`FX.nameScatter` |
| 7 | 結果 | 7.0s+ | 姓名與部門持續顯示、粒子飄落、背景光暈緩慢呼吸 | 殘響 | `result`、`sparkle` |

### 7.1 節奏自動調整

| 情境 | 調整 |
|---|---|
| 頭獎（tier 1） | 翻牌 ×1.3、蓄勢 1.5s、衝擊與彩帶 ×1.7、號角 6 音 |
| 二獎（tier 2） | 翻牌 ×1.12、紅金色系、號角 5 音 |
| 三獎（tier 3） | 翻牌 ×0.9、紫色系 |
| 參加獎（tier 4） | 翻牌 ×0.75、青色系、節奏最快 |
| 一次抽 ≥ 6 人 | 整體 ×0.78，逐位揭曉 |
| 一次抽 ≥ 12 人 | 整體 ×0.55（20 位約 1.5 分鐘內完成） |

### 7.2 多人揭曉

- 每位中獎者單獨跑一次完整曲線（保留每一次的緊張感）。
- 已揭曉者收進下方卡片牆；超過 8 人自動縮小字級（`.winners.many`）。
- 全部完成後大字收起、卡片牆放大，方便全場一次看完。

## 8. 功能規格

| 功能 | 規格 |

## 9. 效能與相容性

- **資料量**：300 人名單 + 50 筆中獎紀錄 ≈ 40KB，localStorage 存取 <5ms。
- **畫面**：單一 Canvas + CSS transform 動畫，投影機 1080p 可穩定 60fps。
- **瀏覽器**：Chrome / Edge 100+（建議）、Firefox 110+。需支援 `color-mix()`、`BroadcastChannel`。
- **檔案開啟**：直接 `file://` 開啟即可；不需本機伺服器。

## 10. 風險與備援

| 風險 | 影響 | 備援 |
|---|---|---|
| 投影視窗關閉／當掉 | 沒有動畫 | 控制台偵測斷線並提示；可選擇「仍然抽出」直接記錄，或重開投影畫面 |
| 投影機故障 | 觀眾看不到 | 控制台仍有完整中獎紀錄，可事後公告 |
| 誤抽／抽錯人 | 公平性 | `Ctrl + Z` 整輪撤銷，人員自動回池 |
| 名單有誤 | 抽到不在場者 | 名單頁「排除」勾選；或撤銷後修正名單重抽 |
| 停電／瀏覽器關閉 | 資料遺失 | 每次操作即寫入 localStorage；活動前後各匯出一次 JSON |
| 音效沒出來 | 氣氛不足 | 檢查是否點過投影畫面、系統輸出裝置；不影響流程 |
| 現場網路斷線 | 無影響 | 系統完全離線 |
| 同名同姓 | 辨識困難 | 顯示部門；員工編號可開啟；必要時同名加序號 |

## 11. 驗收清單

- [ ] 300 人名單匯入正確，無亂碼、無重複
