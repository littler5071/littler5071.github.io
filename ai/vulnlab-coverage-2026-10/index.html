2026-10-28｜小R 頻道｜AI 技術觀察／資安實測

一句話版本：我寫了三支「故意有漏洞」的程式（Rust／C#／Python），每個都植入同一組 6 種弱點，再加一個已知漏洞的相依套件，共 20 個弱點。用 11 個免費工具去抓，全部工具聯集只命中 13／20（65%）：Python 100%、C# 71%、Rust 17%。沒有任何單一工具能單獨應付歐盟 CRA。

三、掃描範圍會決定你看到什麼（實測對照）

同一個專案，只換「掃哪裡」，數字就完全不同。這是 CRA 證據最常出錯的地方：你以為掃了專案，其實掃到的是建置暫存檔。

專案掃描範圍syft 元件grype CVEtrivy CVEtrivy secret
RustS1 只掃原始碼9110
S2 只掃成品（target/release）0000
S3 全目錄（含建置暫存）9110
C#S1 只掃原始碼（排除 obj／bin／out）0000
S2 只掃成品（out/）5200
S3 全目錄40012100
PythonS1 只掃原始碼317171
S2 只掃成品（PyInstaller 單檔）0000
  • C# 只掃原始碼 → 0 個元件：.NET 的相依資訊在 obj/project.assets.json，把它排除就什麼都掃不到。
  • C# 全目錄 → 400 個元件、12 個 CVE：其中大部分是建置暫存與 runtime 檔案，SBOM 會被灌水，sbomqs 分數也被拖低。
  • 只掃成品 → 多數是 0：strip 過的 ELF 與單檔打包沒有相依線索。
  • 結論：掃描範圍要等於「出貨內容＋lockfile」，並在證據上寫明範圍與 commit／digest。

四、連平台也一起：Windows／Linux／ARM64（含 Apple M 系列）

  • Rust：x86_64-unknown-linux-gnu（ELF）、x86_64-pc-windows-gnu（PE32+）、aarch64-unknown-linux-gnu（ELF ARM64）、aarch64-apple-darwin（Mach-O arm64，即 M 系列）。後三者用 Zig 0.17.0 當連結器（cargo zigbuild），完全在 Linux 上完成。
  • C#：dotnet publish -r win-x64／linux-x64／linux-arm64／osx-arm64 --self-contained -p:PublishSingleFile=true，四個 RID 都成功。
  • Python：Linux x86_64 用 PyInstaller 打成 ELF；Windows 用官方 embeddable Python 打包成可攜 zip（PyInstaller 無法跨平台編譯）；ARM64 沒有現成免費方案，這點照實說。

掃描 ARM64 成品時發現：Rust 的 arm64 ELF 與 Mach-O 都抓到 0 個元件（strip 過）；C# 的 linux-arm64 目錄因為還有 deps.json，抓到 5 個元件、grype 找到 2 個 High；osx-arm64 是單檔，抓到 0 個。結論：SBOM 一定要在 build 階段產生，事後掃執行檔幾乎掃不到東西。

唯一三個語言都 100% 命中的類型，是「相依套件漏洞」。這也是為什麼 CRA 把 SBOM 寫成硬性要求——它是目前唯一可靠的自動化防線。

九、結論：CRA 要的是三件套，不是一個神器

  1. SBOM：build 階段用 syft 產生（事後掃執行檔會得到 0 個元件），用 sbomqs 檢查 BSI／NTIA profile。
  2. SCA：grype＋trivy＋OSV 至少並跑兩個，保留原始 JSON 當證據。
  3. SAST：按語言挑——Python 用 Bandit、C# 用 .NET 分析器、Rust 老實說沒有成熟的免費方案。
