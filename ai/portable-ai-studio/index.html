1,500 星的離線 AI 工作室實測：
配音比實時慢，字幕卻快 2 倍

同一台文書機，把它裡面兩個引擎單獨拿出來量：哪些值得留、哪些不值得裝
2026/10/13・實測報告（無影片）
這套 GUI 不用裝；但它裡面有兩個引擎值得單獨拿出來用， 其中一個（faster-whisper）我實測之後會繼續用。 同一句話、同一台沒有獨立顯示晶片的文書機上： 中文配音 RTF 1.30（比實時慢）、 雲端語音 0.10、 語音轉文字 0.48（比實時快 2 倍）。

先看速度：三個引擎的實時倍率（RTF）

把這次實測的三個引擎放在同一把尺上比。單位是 RTF（Real-Time Factor）＝ 合成或辨識耗時 ÷ 音訊長度—— 小於 1 才叫「比實時快」。長條越短表示越快。

Kokoro 中文配音完全離線・ONNX
1.30慢於實時
edge-tts 中文語音連微軟雲端
0.10快 13 倍
faster-whisper 中文辨識small・int8・CPU
0.48快 2 倍
↑ 1.0＝實時分界（虛線）

長條越短表示越快；1.0 是在這台機器上「比實時慢」的分界。 Kokoro 的 1.30 是四個中文聲音的代表值（實測範圍 1.25～1.35）； edge-tts 的 0.10 來自同一句話的對照組。三個數字都是同一台機器、同一段文字。

先講結論：四個功能，我只留一個

它的四個功能在這台機器上我的判斷
圖片生成（Stable Diffusion） 未實測（推估：SDXL 每張 10～30 分鐘、SD1.5 每張 2～5 分鐘） ✗ 不用裝
文字對話（GGUF LLM） 未實測（CPU 可跑但慢） ✗ 已有更好的
文字轉語音（Kokoro-82M） 實測完成：比實時慢 1.25～1.35 倍 ⚠ 可當第二個聲音，不是主力
語音轉文字（Whisper） 實測完成：1 秒語音只花 0.48 秒辨識，且 7 段全對上 ✓ 這個我會繼續用

要裝那整套嗎？不用。那兩個引擎直接從官方 PyPI 安裝（約 1 GB、 不碰它附的 .bat）就能跑，而且同一件事的速度快得多。

它是什麼

一個完全離線的 AI 工作室，把四件事包進一個圖形介面， Windows／Linux／macOS 都能跑。特色是零安裝： 雙擊它附的批次檔，它會自己下載一份可攜的 Node.js 與 GPU 後端， 裝完打開本機的 localhost:1420 就能用。標榜 100% 離線、 不上傳、不用登入、不用 API key。

  • 圖片生成走 stable-diffusion.cpp（吃 .safetensors／.ckpt，SD1.5 與 SDXL 單檔模型）
  • 文字對話走 llama.cpp（吃 .gguf）
  • 語音轉文字走 whisper.cpp
  • 文字轉語音走 Kokoro-82M（ONNX）

受測的是 Portable AI Studio （techjarves/Portable-Local-Studio）。

要提醒一點：它的安裝方式是雙擊批次檔，腳本會自己下載 Node 與 GPU 後端二進位檔。 這種來路不是官方發行版的東西，要跑之前最好先把它的安裝腳本讀過一遍， 或是像我一樣只裝引擎、不跑那個檔。

RTF（Real-Time Factor）＝ 合成耗時 ÷ 音訊長度。小於 1 才是「比實時快」。

結論：Kokoro 的中文聲音確實可用，但在這台上 RTF 1.25～1.35， 意思是生成 1 秒的聲音要等 1.3 秒。換算成實際工作： 一支 54 秒的影片旁白，要等約 70 秒——等得起，但明顯比 edge-tts 慢。

② 對照組：edge-tts（同一句話）

引擎音長合成耗時RTF
edge-tts HsiaoChen10.87 秒1.05 秒0.10
Kokoro zf_xiaoxiao8.47 秒11.41 秒1.35

edge-tts 快 13 倍（同樣一句話，1 秒對上 11 秒）， 而且實測音量也比較飽（對照 Kokoro 的 RMS 0.063～0.100）。

但要注意：edge-tts 是連到微軟雲端的服務（所以快）， 而 Kokoro 完全離線。兩者取向不同： 要快要自然 → edge-tts；要斷網也能用、不想連外 → Kokoro。

③ faster-whisper 中文辨識

拿當天剛做好的一支 54 秒短片直接轉字幕：

模型           small（int8，CPU）
模型載入       42.7 秒
辨識耗時       26.1 秒（54 秒的音訊）
RTF            0.48  ← 1 秒語音只花 0.48 秒辨識，比實時快 2 倍
語言判斷       zh（信心 1.00）
切出段數       7 段

最讓我意外的是切段：它切出來的 7 段時間，跟我影片設計的 7 格幾乎完全吻合 （0-9／9-16／16-22.5／22.5-31.5／31.5-38.4／38.4-42.9／42.9-50.7 秒）， 等於可以直接拿來上字幕，時間軸不用重做。

我的建議

  • 1. 不要裝那整套 GUI　圖片生成在這台沒有獨立顯示晶片、跑不動 （還要另外下載 2～7 GB 的模型）；文字對話我們已經有更好的。 為了兩個引擎去裝一整套、又跑一個來源不明的批次檔，不划算。
  • 2. 要裝就只裝引擎（我就是這樣測的，約 1 GB，全部來自官方 PyPI）： 
    # 語音轉文字（推薦）
uv pip install --python <venv> faster-whisper soundfile
# 中文語音（可選）
uv pip install --python <venv> kokoro "misaki[zh]"
    faster-whisper 是這次最值得的收穫—— 以後做影片可以自動上字幕（RTF 0.48，54 秒影片 26 秒轉完）。
  • 3. Kokoro 當第二個聲音選項，不要當主力。它的價值是完全離線 （edge-tts 要連微軟）＋聲音比較沈穩。等哪天 edge-tts 又掛掉，它就是備援。
  • 4. 順帶一提：裝 Kokoro 時它把 transformers 從 4.48 升到 5.19（跨大版本）。 測完確認影片流程沒有依賴它（edge-tts／numpy／PIL／soundfile 全部正常），所以沒有影響， 但這種跨版本升級值得每次都檢查一次。

附錄：可重現的做法

測試腳本與原始數據保存在本機，以下是兩個引擎的最小可重現範例。

# Kokoro 中文
from kokoro import KPipeline
import soundfile as sf
import numpy as np

pipe = KPipeline(lang_code="z")
chunks = [a for _, _, a in pipe("要唸的中文", voice="zf_xiaoxiao")]
sf.write("out.wav", np.concatenate(chunks), 24000)   # 24000 Hz

# faster-whisper 中文辨識
from faster_whisper import WhisperModel

m = WhisperModel("small", device="cpu", compute_type="int8")
segs, info = m.transcribe("audio.wav", language="zh", beam_size=5, vad_filter=True)
for s in segs:
    print("[%.2f-%.2f] %s" % (s.start, s.end, s.text.strip()))

Kokoro 的中文聲音一覽：女聲 zf_xiaobei／zf_xiaoni／ zf_xiaoxiao／zf_xiaoyi，男聲 zm_yunjian／zm_yunxi／ zm_yunxia／zm_yunyang。

一句話收尾

這套 GUI 不用裝。真正值錢的是它裡面選的引擎—— faster-whisper 我實測後會繼續用來上字幕， Kokoro 則留著當離線備援。至於圖片生成與文字對話，這台沒有獨顯就先不用想了。
