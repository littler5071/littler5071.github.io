AI 公司真的都在改用 Rust 嗎？我查了 GitHub 原始數據，答案是「一半對」

2026-10-27｜小R 頻道｜AI 技術觀察

一句話版本：「AI 公司都在轉 Rust」對一半。轉的是模型外面的東西——推論引擎、分詞器、套件管理器、CLI、資料處理，這些幾乎都換成 Rust 了（實測佔比 62%～98%）；但模型本身還是 Python 的天下，PyTorch 的 Rust 佔比是 0%。所以正確說法是：引擎沒換，管線換了。

一、這個說法從哪裡來

2026 年社群上很流行一句話：「AI 公司都在把程式碼改寫成 Rust，GitHub 上越來越多專案大量使用 Rust。」這句話在工具鏈層面是真的，在模型層面是錯的。兩個說法混在一起講，就變成一個看起來很猛、但經不起查證的結論。

我不用二手轉述，直接查原始資料：GitHub 的語言統計 API（每個 repo 各語言實際的程式碼位元組數）、公司官方公告、Linux 核心維護者的會議紀錄。

二、我怎麼查的（可重現）

GitHub 對每個公開 repo 都有語言統計端點，回傳的是各語言實際的程式碼位元組數，不是我猜的。查詢方式：

再加上兩個「不是程式碼佔比、但更關鍵」的事實：

  • OpenAI 在 2026 年 3 月宣布收購 Astral（uv、Ruff、ty 的開發團隊），官方新聞稿寫明要把這些工具整合進 Codex 生態。
  • Linux 核心的 Rust 支援在 2025 年維護者峰會正式「實驗過關」，Miguel Ojeda 在會中說 Rust 程式碼量一年成長五倍；Android 16（6.12 核心）已經出貨含 Rust 寫的 ashmem 模組，NVIDIA 的 Nova 驅動也陸續合併。

四、反向驗證：如果「都在轉」，龍頭不會是 0%

只列對自己有利的數據不算證明，所以我又查了對照組——PyTorch，AI 模型訓練的事實標準：

語言佔比說明
Python66.3%模型定義、訓練腳本、整個研究生態
C++26.5%底層運算核心
CUDA2.5%GPU kernel
Rust0%完全沒有

PyTorch 的 repo 裡，Rust 一行都沒有。如果「AI 公司都在轉 Rust」講的是模型本身，這個數字不會長這樣。

五、那為什麼大家一直說 Rust？

因為 Rust 解決的是 AI 產品上線之後才會痛的三件事：

痛點Python 的問題Rust 的做法
延遲垃圾回收（GC）造成偶發停頓沒有 GC，延遲曲線平穩
記憶體長時間執行的服務容易漏編譯期就擋掉記憶體錯誤
成本同樣流量需要更多機器常駐記憶體小、CPU 用得省

這些正好是推論服務、分詞、資料前處理、CLI 工具最在意的事——也就是「模型外面那一圈」。模型訓練反過來：研究要的是生態、實驗速度、現成的套件，Python 完勝，而且短期不會變。

六、什麼轉了、什麼沒轉

層現在的主流有沒有轉 Rust
模型訓練／研究Python ＋ CUDA／C++沒有（PyTorch 0%）
推論引擎、分詞器Rust（tokenizers 95%）大幅轉
開發工具鏈Rust（uv 98%、ruff 97%）幾乎全轉
資料處理Rust 核心 ＋ Python 介面（Polars 62%）轉一半，介面留 Python
作業系統／驅動C 為主，Rust 快速增加進行中（核心 Rust 一年 5 倍）

八、對不同人的意義

  • 如果你在寫 AI 應用：你不用改學 Rust，但你用的工具會慢慢變成 Rust 寫的（uv、ruff、tokenizers），速度變快是白拿的好處。
  • 如果你在做服務、要壓延遲與機器成本：Rust 值得學，尤其是推論服務、資料處理這段「Python 很貴」的地方。
  • 如果你在研究模型：繼續用 Python。這幾年不會有「模型用 Rust 寫」的轉折，社群的實驗速度比語言效能重要。

九、一句話結論

「AI 公司都在轉 Rust」要加一個很長的但書：轉的是模型外面的管線，不是模型本身。看到有人拿幾張 Rust 佔比圖就說「Python 要被取代」，先問他一句：那 PyTorch 的 0% 怎麼解釋？
