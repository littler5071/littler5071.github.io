兩天內兩個 9.2 級漏洞：PHP 緊急修補、Python 換掉被駭的憑證

2026-10-23｜小R 頻道｜資安事件解讀

一句話版本：10 月 21 日，PHP 修掉兩個「不用登入就能執行任意程式碼」的漏洞（CVSS 9.2）；同一天 Python 發了三個版本，但修的不是程式本身，而是憑證信任鏈——eMudhra 八張中繼憑證的私鑰被偷，拿到金鑰的人可以假冒任何網站。

一、PHP：兩個 9.2 級漏洞，同一天修掉

PHP 專案在 2026 年 10 月 21 日發布 8.5.12、8.4.27、8.3.36、8.2.35，修補兩個嚴重度 9.2（CVSS v4.0）、可讓未登入攻擊者執行任意程式碼的漏洞。兩個漏洞都位在「幾乎每個請求都會經過」的地方：記憶體管理與錯誤處理。

漏洞一CVE-2026-109618：記憶體爆掉時狀態沒清乾淨

RCE via OOM corruption

當請求剛好在 memory_limit 邊界觸發記憶體不足，PHP 會留下「只初始化一半」的內部資料；後續的清理流程把這塊無效資料當成有效資料處理，造成記憶體毀損。在 Apache + mod_php 環境下，連應用程式碼都還沒開始執行就能觸發，官方表示預設設定即可達到遠端程式碼執行。

這也是為什麼它嚴重：你以為「我的程式寫得很安全」沒有用，因為攻擊發生在你的程式之前。

漏洞二CVE-2026-109619：殘留的全域狀態被下一個請求接手

RCE via stale global state

請求在錯誤的時間點發生致命錯誤後，PHP 的內部狀態仍指向已經被釋放的記憶體。同一個 worker 處理下一個請求時，可能會用到這塊殘留狀態。已確認可造成 use-after-free 與 worker 崩潰，也確認可達成遠端程式碼執行。

PHP-FPM 也受影響，只是需要經過應用程式的程式碼路徑；Apache + mod_php 風險最高。

修補方式

項目內容

二、Python：不是程式漏洞，是憑證鏈被攻破

同一天（10/21），Python 發布 3.15.1、3.14.9、3.13.17，三個版本都把內建 pip 升到 26.2.2，其中包含 certifi 2026.10.19，用來移除已被撤銷的 eMudhra／emSign 中繼憑證。

事件的源頭不是 Python：印度憑證機構 eMudhra 的 8 張中繼憑證私鑰外洩。10 月 17 日有人用這些私鑰簽署訊息通報，證明金鑰真的被拿走；10 月 20 日公開揭露。Firefox 與 Chrome 已在 17 日起封鎖這些中繼，微軟 20 日、蘋果 22 日跟進。

問題在於：瀏覽器有撤銷清單機制，會自動更新；但你程式裡帶的憑證包不會。 只要某個 venv 的 certifi 還留著舊的憑證包，它就會繼續信任這八張中繼——攻擊者就能用它簽發的憑證假冒任何網站，包括你呼叫的 API 或套件下載來源。

五、常見問題

Q：我用 Docker 跑 PHP，映像有更新嗎？
A：官方映像通常會重建，但要自己 pull 新的 tag 並重新部署；只重啟容器不會換到新版本。

Q：PHP 8.1 還能用嗎？
A：官方已停止維護，這次沒有補丁。少數發行版（例如某些 LTS）會回補，要直接問你的廠商；長期還是要升級。

Q：Python 的漏洞不是說「不是程式漏洞」嗎，為什麼要更新？
A：因為你的程式信任哪些憑證，是由 certifi 決定的。舊的 certifi 還信任被駭的中繼，更新程式本身沒用，要更新憑證包。

Q：更新完要做什麼驗證？
A：php -v 確認版本、python -m pip -V 確認 26.2.2、再跑一次你的服務健康檢查。
